Executive Summary & Abstract

The Student Internship Tracker is a web-based database application designed to simplify and streamline the internship recruitment workflow for university students. As the modern recruitment landscape shifts toward high-volume online applications, students face immense organizational overhead across diverse job boards. This system provides a unified interface for tracking application statuses, interviews, technical assessments, and offer deadlines while maintaining robust database integrity via Python Flask and MySQL.

Problem Statement (Institutional & Social Context)

In contemporary computer science and engineering education, securing an internship is a mandatory academic milestone and a critical stepping stone to professional employment. However, the modern hiring process has evolved into an overwhelming digital maze. A single student submits between 50 to 200 applications per recruiting season across fragmented portals like LinkedIn, Handshake, Indeed, and enterprise Workday portals.

Requirement Engineering & System Constraints

4.1 Functional Requirements (FR-01 to FR-05) Verified against software tests

FR-01 Authentication

User Authentication Module

Secure user registration, Werkzeug bcrypt 12-round salt hashing, and cookie-based session token management.

FR-02 CRUD Logging

Application Logging

Form validation capturing company name, role title, career portal URL, submission date, and geographic location.

FR-03 FSM Transition

Lifecycle Management

Finite status progression: Applied → OA Scheduled → Tech Interview → Offer Accepted / Declined / Rejected.

FR-04 Time-Critical

Deadline Tracker & Alerts

Maintains upcoming coding assessments and onsite interviews, dynamically highlighting items due within 48 hours.

FR-05 Search & Filtering

Dynamic Search & Filter Engine

Sub-second client and server-side filtering by pipeline stage, keyword search for companies, and sortable submission dates.

4.2 Non-Functional Requirements (NFRs)

NFR-01: Performance Page load and REST API endpoint responses deliver in ≤ 1.5 seconds under standard broadband conditions.
NFR-02: Security & SQLi Immunity No plaintext passwords stored. Parametrized SQL query placeholders (%s) eliminate SQL injection vulnerabilities.
NFR-03: Accessibility & Responsive UI WCAG compliant contrast, mobile viewport support (min-width: 320px), and clear toast feedback messages.
NFR-04: Reliability & Integrity Target availability 99.5%. Strict foreign keys with ON DELETE CASCADE prevent orphaned rows.

System Architecture & Software Design (MVC)

The Student Internship Tracker strictly adheres to the Model-View-Controller (MVC) architectural pattern, ensuring clean separation of concerns, rapid feature iteration, and maintainable backend code.

M

Model Layer (MySQL / PyMySQL)

Encapsulates database schemas, RAW parameterized SQL execution, data integrity constraints, and session persistence.

Files: models/user_model.py, models/application_model.py
V

View Layer (Jinja2 / Web Client)

Renders presentation markup, dashboard counters, live Kanban status indicators, and modal submission inputs.

Files: templates/base.html, templates/dashboard.html
C

Controller Layer (Flask Routes)

Intercepts HTTP requests, validates auth tokens, communicates with models, and dispatches JSON or HTML responses.

Files: routes/auth_routes.py, routes/tracker_routes.py
